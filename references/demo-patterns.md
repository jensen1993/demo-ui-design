# Demo design patterns

Choose only the patterns needed for the requested flow. Establish a clear focal point, consistent rhythm, concise labels, and realistic text and data. Avoid repeating the same card grid across unrelated products.

- **Operations/CRM:** Prioritize primary tasks and information density. Use a restrained navigation shell, useful filtering, readable tables, meaningful status indicators, and a detail or edit flow. Give summary figures context and keep table actions discoverable.
- **Commerce/service:** Make the core offering visually compelling with appropriate product imagery, concise benefits, price or key details, and a clear action. Provide plausible item, cart or booking states only where in scope; simulate transactions clearly.
- **Consumer mobile:** Use an obvious screen hierarchy and comfortable touch targets. Account for device safe areas, long text, scrolling, keyboard and bottom navigation as relevant. Choose image, list, and card treatments that suit the content rather than scaling down a desktop dashboard.
- **SaaS/brand landing:** Explain the offering in the first screen; use typography, visual rhythm and a fitting hero treatment. Support the main call to action with believable features or examples rather than generic filler.
- **Analytics:** Make the decision or insight the focus. Use plausible values, units, date ranges and legends. Select chart types for the data and make status distinguishable without relying on color alone.

For an interactive demo, prioritize one complete journey over many nonfunctional buttons. Reuse project assets or properly licensed materials; use generated visuals only when appropriate and available. Avoid embedding remote image or icon links that make the demo unusable offline unless the context permits it. Do not fabricate claims of production readiness.
